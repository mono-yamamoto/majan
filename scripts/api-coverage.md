# API 経路の網羅表

`src/lib/api.ts` の export（＝画面が叩ける経路）と、**画面から渡しうる入力の種類**を突き合わせた表。
空欄があれば `scripts/verify-api.sh` に検査が無いということ。

## なぜ表を作るか（原則8）

「ユニットテストで見ている」と「API 経由で通る」は別。
実際に、T13 で予約の3区分をユニットテストで固めた一方、**API 経由で予約が作れるかは一度も確認していなかった**。
`stats.ts` / `validation.ts` のテストが充実していたので、経路の抜けに気づけなかった。

**画面の操作1つにつき、`verify-api.sh` のケースを1本以上対応させる。**
機能を足すときは、この表に行か列を足してから `verify-api.sh` を書く。

## 経路（`src/lib/api.ts` の export）

| export         | HTTP                           | 呼び出し元の画面                    |
| -------------- | ------------------------------ | ----------------------------------- |
| `fetchLeagues` | `GET /api/leagues`             | `LeagueIndex`（トップのリーグ選択） |
| `fetchLeague`  | `GET /api/leagues/:id`         | `LeagueProvider`（全画面の土台）    |
| `createGame`   | `POST /api/games`              | `NewGamePage`（半荘登録）           |
| `updateGame`   | `PATCH /api/games/:id`         | `EditGamePage`（半荘編集）          |
| `deleteGame`   | `PATCH /api/games/:id/deleted` | `EditGamePage`（削除）              |

## 入力の種類 × 経路

`—` は経路として存在しない組み合わせ。`N/A` は API 経由では到達できない（フォーム専用）。

### 半荘の中身

| 入力の種類                           | `POST`                                        | `PATCH`                                      |
| ------------------------------------ | --------------------------------------------- | -------------------------------------------- |
| 確定（4人・全員数値・2-2・合計一致） | ✅ 正常な POST                                | ✅ leagueId なし                             |
| 予約（4人・全員 null）               | ✅ title 付きの予約は通る                     | ✅ 確定 → 予約に戻す                         |
| **箱下（負の素点を含む）**           | ✅ 箱下（負の素点）を含む確定                 | ✅ 箱下に編集する                            |
| 予約 → 確定                          | —                                             | ✅ 予約 → 確定（素点を入れる）               |
| 確定 → 予約                          | —                                             | ✅ 確定 → 予約に戻す                         |
| メンバーの総入れ替え                 | —                                             | ✅ メンバーを 1,6,2,7 → 3,8,4,9 に総入れ替え |
| 同じ日にもう1半荘                    | ✅ 同じ played_on でもう1半荘                 | —                                            |
| 同じ日に予約と確定が混在             | ✅ 同じ日に予約も作る                         | —                                            |
| **別リーグへの登録**                 | ✅ リーグ2の正規メンバーなら 201              | —                                            |
| 別リーグのメンバーを混ぜる           | ✅ リーグ2にリーグ1のメンバー → NOT_IN_LEAGUE | —                                            |

### バリデーション（`validation.ts` の `ValidationErrorCode`）

| コード                   | `POST`                              | `PATCH`                                  |
| ------------------------ | ----------------------------------- | ---------------------------------------- |
| `RESULT_COUNT`           | ✅ 3件のときのコードは RESULT_COUNT | ✅ PATCH で3件 → RESULT_COUNT            |
| `DUPLICATE_MEMBER`       | ✅ 同じ人を2回 → DUPLICATE_MEMBER   | —                                        |
| `MEMBER_ID_RANGE`        | ✅ memberId が 0 → MEMBER_ID_RANGE  | —                                        |
| `NOT_IN_LEAGUE`          | ✅ リーグ未所属メンバー             | —                                        |
| `TEAM_BALANCE`           | ✅ 2-2 でない                       | ✅ PATCH で 2-2 を崩す → TEAM_BALANCE    |
| `RAW_SCORE_TOTAL`        | ✅ 素点合計が違う                   | —                                        |
| `RAW_SCORE_UNIT`         | ✅ 100の倍数でない → RAW_SCORE_UNIT | —                                        |
| `RAW_SCORE_NOT_A_NUMBER` | **N/A**                             | **N/A**                                  |
| `RAW_SCORE_RANGE`        | **N/A**                             | **N/A**                                  |
| `INVALID_DATE`           | ✅ 日付が実在しない                 | —                                        |
| `TITLE_REQUIRED`         | ✅ 無し / 空文字 / 空白だけ         | ✅ null / 省略 / 空白だけ                |
| `TITLE_TOO_LONG`         | ✅ title 61文字                     | —                                        |
| `MIXED_SCORES`           | ✅ 素点が一部だけ                   | ✅ PATCH で素点を一部だけ → MIXED_SCORES |

`RAW_SCORE_NOT_A_NUMBER` と `RAW_SCORE_RANGE` が **N/A** なのは、`parseGameInput` が
`rawScore` に安全整数か `null` しか通さないため。API 経由ではこの2つより手前の 400
（`must be a safe integer or null`）になる。JSON に `NaN` リテラルは書けない。
**フォーム側の経路は `validation.test.ts` が持っている。**

### 削除（`PATCH /api/games/:id/deleted`）

| 入力の種類              | 検査                                                      |
| ----------------------- | --------------------------------------------------------- |
| 確定の削除              | ✅ 1回目の削除                                            |
| **予約の削除**          | ✅ 予約を削除する                                         |
| 同じ削除の再送（冪等）  | ✅ 2回目の削除（再送・冪等）／deleted_at が上書きされない |
| 復活（`deleted:false`） | ✅ deleted:false（復活）                                  |
| 非 boolean              | ✅ deleted が非 boolean                                   |
| 存在しない id           | ✅ 存在しない :id の削除                                  |
| 削除済みへの編集        | ✅ 削除済みへの PATCH                                     |

### レスポンスの形（フロントが依存している）

| 形                                                  | 検査                                    |
| --------------------------------------------------- | --------------------------------------- |
| `{ leagues: [{id, name}] }` / id 降順               | ✅ GET /api/leagues の4件               |
| `LeagueResponse.games[].results[]` が4件            | ✅ GET の各半荘が4人ぶんの結果を持つ    |
| **予約が `rawScore: null` で返る**                  | ✅ GET で予約は rawScore が null で返る |
| 削除済みが GET に出ない                             | ✅ 削除済みの id=1 が GET に含まれない  |
| 400 が `{ errors: [...] }` / 形の不正が `{ error }` | ✅ 400 のボディ形状の5件                |

`valueFromGame` は `rawScore === null` を「予約」と読む。ここが `0` や欠落に変わると
**フォームが素点 0 の確定として開く**ので、形そのものを固定している。

### 認証・入口

| 種類                           | 検査                                               |
| ------------------------------ | -------------------------------------------------- |
| パスコード無し / 誤り / 空文字 | ✅ POST ヘッダ無し・誤り・空文字                   |
| GET はパスコード不要           | ✅ GET /api/leagues はパスコード不要               |
| `WRITE_PASSCODE` 未設定 → 500  | ✅ 未設定 + ヘッダ無し/有り → 500                  |
| ボディ 16KB 超 → 413           | ✅ ボディ 16KB 超（`readJson` は POST/PATCH 共有） |
| JSON 壊れ → 400                | ✅ JSON 壊れ（同上）                               |
| 存在しないリーグ / 半荘        | ✅ 存在しない leagueId / :id                       |

### 初期データ（`db/seed.sql` / `db/roster.sql`）

API ではないが、運営が本番で流すファイルなので同じ扱いにする。
**二重投入の挙動が2ファイルで逆**なのが設計そのものなので、両方を固定する。

| 種類                              | 検査                                          |
| --------------------------------- | --------------------------------------------- |
| 2ファイル構成で名簿がそろう       | ✅ seed + roster でメンバー10人／所属も10行   |
| **`roster.sql` は何度でも流せる** | ✅ 2回目でも行が増えない（members / 所属）    |
| 名前の打ち直しが効く              | ✅ 名前が置き換わる／名前も戻る               |
| **チーム分けの変更が効く**        | ✅ チーム分けが置き換わる／流し直すと元に戻る |
| 他の人を巻き込まない              | ✅ 他の人の所属は変わらない                   |
| **`seed.sql` は二重投入で落ちる** | ✅ UNIQUE で落ちる／リーグは1件のまま         |

### 検査していないと決めたもの

| 対象                           | 理由                                                             |
| ------------------------------ | ---------------------------------------------------------------- |
| `wrangler deploy` / `--remote` | 本番DBに触るので検証スクリプトから完全に外す。T11 は運営の手作業 |
| `PATCH` の 413 / JSON 壊れ     | `readJson` が `POST` と共有の実装。`POST` 側を代表とする         |
| フォームの表示・遷移           | ブラウザでの実機確認（各タスクの報告に記載）                     |
